# 语义验证

这个 Skill 验证材料和证据是否足以支持结论，不替代 Cargo、契约、集成或发布门禁，也不输出绝对安全评级。
先调用 `semantic-contract` 执行确定性结构检查并取得合同版本；结构未通过时不得继续语义结论。

## 三层检查

1. **结构**：解析 Markdown 前置元数据，检查必填字段、枚举、唯一标识、目录与 `kind`、引用存在、能力图归属、
   场景处置、区域覆盖和 `primary_focus`。
2. **语义**：对照期望、当前实现、规则、证据、问题记录和审查版本；检查两层闭合是否有依据，
   是否存在未映射变化、悬空边界、隐藏未知或失效对象。
3. **执行**：只有静态事实不足或解决条件明确要求运行结果时，才运行对应的测试、契约检查或脱敏场景。

## 状态条件

- `risk_accepted` 必须有人的裁决引用；
- `resolved` 必须有修复、验证和复审证据；
- `examined` 只表示列出的故障假设已在指定 revision 检查，不表示没有问题；
- 发现快照漂移、缺失证据或失败命令时保持未完成，并列出下一步。

验证结果应说明命令、源码版本、退出码、覆盖范围和不能证明的内容。禁止使用 `clean`、`safe`、
“已证明没有缺陷”等结论。
