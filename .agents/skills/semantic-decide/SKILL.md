# 语义裁决

主 Agent 负责发现和取证，人只处理不可从源码、契约或测试推导的产品选择。一次裁决只提出一个问题，避免让
人同时重写多个对象。
写回前调用 `semantic-contract`，确认目标对象、状态和引用字段；没有具体目标对象时不得创建裁决记录。

## 裁决单元

展示：重要承诺、当前行为、已有期望或冲突、关键证据、风险、受影响对象，以及唯一待决定的问题。
选项通常是确认期望、修正期望、接受残余风险或暂缓并补充信息。

## 写回规则

- 确认或修正期望时写回原行为承诺或规则，并保留裁决来源和时间。
- `risk_accepted` 必须引用人的明确裁决；普通缺陷不能因为尚未有人查看就进入该状态。
- 暂缓不改变原状态，不把未知当成批准，也不创建平行对象。
- 人确认的期望是受保护事实；后续差异可以使实现变为 `stale`，但不能自动改写该期望。

不要替人决定架构、兼容性、公共契约或风险取舍，也不要直接修改业务代码。

裁决写回后调用 `semantic-verify`；若裁决要求修改代码，回到正常设计/计划/构建流程，代码形成差异后再调用
`semantic-diff`。
