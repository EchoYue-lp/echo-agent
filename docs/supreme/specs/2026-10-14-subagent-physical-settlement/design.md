## Problem and outcome

A historical real `TeamRuntimeHandle` with held stream cleanup returned after grace, published Cancelled, and cleared its claim while the original producer remained alive. Diagnostic source is recoverable at `286715f9bb8d7a7102dbf9da4199bc2b7e43814d` / `refs/echo-semantic/diagnostics/subagent-stream-grace-held`; it is a b909 counterexample, not an executed result on current 00782. Current source independently retains exact scheduled abort, root abort_all, unwind abort_all and managed producer abort, so current-source red tests must precede repair claims.

After cancellation, observation may expire while physical work is still cleaning. Only actual original producer closure followed by the same claim CAS establishes terminal settlement. Normal execution has no observation timer.

## Boundary and reuse

This is a framework mechanism independent of EKO or any SDK. Reuse the one revisioned task store, live claim/control projections, original join/watch owners, permits, cancellation tokens and admission. No new TaskStatus, store, scheduler, replacement execution, second cleanup registry or transport. Standard Tokio retained tasks, JoinHandle, cancellation tokens and watch channels supply the ownership/observation primitives; no dependency is added.

Original Subagent Sync/Fork/Teammate invocation and rich event translation remain authoritative. The event normalizer is a delivery projection, so normalized terminal/EOF cannot substitute for raw producer EOF. Invocation/steering/admission/isolation guards remain owned until physical drain.

## Observation and settlement

`RuntimeTaskService::execute` retains its existing spawned execution owner. An observer watches normal completion without a timer. Only its first admitted root cancellation or whole-run pause starts `cancellation_grace_period` (default five seconds). Repeated requests never reset the deadline. Expiry returns `ReactError::ExecutionNotSettled { run_id: String, execution_id: Option<String> }`, with None for the root observer, while the same owner continues. A completed owner wins a simultaneous deadline. Caller drop signals the same child cancellation scope and detaches only its wait.

Exact attempt A interruption returns existing ActiveRequested/ActiveAlreadyRequested immediately, never starts the root observer clock, and never interrupts sibling B. Existing explicit waits for A's already-joined settlement use the first admitted exact request's deadline, not a reset per waiter. Expiry identifies Some(execution_id); current Running/claim/interruption_requested remain. This observation is not a Task terminal, Agent failure, retry authorization, or a new attempt. Mutating requests must not be automatically replayed.

Root cancellation/pause persists the request without settling via a required `RuntimeDagController::request_task_interruption(&self, run_id: &str, task: &Task, claim: &TaskClaim, disposition: RuntimeInterruptionDisposition) -> Result<bool>` adapter hook. It delegates to the existing TaskRevisionService exact-claim request CAS: true means the same claim admitted the durable request; false means mismatch/superseded, never successful admission. Backend failure retains claim and reports unknown. There is no default fake success or second state mutation algorithm; current controller implementers must explicitly migrate. A slow request CAS does not reset the root observation clock or prove completion.

Remove grace-triggered abort from exact attempt scheduling and root wave settlement. On driver unwind the existing wave owner signals original tokens, retains and drains the original JoinSet, and only settles each physically joined claim. A panic/lost physical owner without a closure receipt publishes existing AuthorityUnknown and retains durable claim/interruption_requested rather than assuming abandonment proves stop. No broad catch-and-success.

The exact-interruption API already returns `RuntimeTaskAttemptInterruptError`, not `ReactError`. Its existing error boundary therefore carries a typed not-settled observation with the same run/execution identity and converts losslessly to the sole canonical `ReactError::ExecutionNotSettled`. It is not a second terminal representation or a new method. First-request timestamps belong to the existing exact attempt control projection and survive repeated requests until that projection settles. A lost-owner AuthorityUnknown is returned as uncertainty, never timed into a terminal.

The Team execution-timeout branch must propagate ExecutionNotSettled before any AgentFailure conversion or reconstruction as AgentError::Timeout. Dispatch classification and resolution boundaries must likewise preserve it. The generic runtime service observer can return it; original dispatch/settlement owners never use it as a replacement dispatch result. Unexpected join failure and root cancellation of a recovered Running claim without physical proof must retain the claim and publish AuthorityUnknown instead of calling blanket abandonment settlement.

One original private spawn helper is shared by `execute` and the minimal cross-crate owner-composition entry `execute_to_settlement`. The latter waits the original JoinHandle without an observer timer and is used only by internal Team dispatch composition, so a nested runtime observation cannot drop its Team active/admission owner. It is a Rust owner-wait API, not an accepted language method. The public external Team observation path retains the bounded observer; the internal path explicitly selects owner waiting without changing execution cancellation or timeout cause. There is no second owner registry or re-execution to recover a timed-out observer's result.

## Stream ownership and cause ordering

Sync, Fork and Teammate retain the same pinned execution future when cancellation or the original execution timeout arrives, signal its token, then drain it. The first observed cancel/timeout/raw error/event failure remains the result cause; later cleanup failure does not erase an earlier cause. Cancellation grace is not another execution timeout. Normal execution timeouts remain configured as before, but timeout return is deferred until cleanup actually finishes in the owned attempt. Dropping an outer caller must transfer its original producer/join ownership to the runtime without abort, releasing permits only after closure. Managed React stream drop uses its existing reaper ownership to drain the original producer instead of aborting it after a timer.

ExecutionNotSettled is observer knowledge. All affected dispatch, Team and React terminal-production boundaries must propagate or exclude it before AgentFailure/subagent terminal classification. It must never create Failed merely to satisfy an exhaustive match. The SDK Host projection is a separate authorized integration: existing framework_error details observation=not_settled/run_id/optional execution_id, mutations Never; no new wire code or automatic accepted cross-language membership.

### Fallible terminal classification

The existing `From<&ReactError> for AgentFailure` is infallible and has no legal nonterminal result. Replace it with `TryFrom<&ReactError>`: ordinary errors retain every existing category, terminal_kind, retryable, code, HTTP status and message; ExecutionNotSettled returns an owned identity-preserving typed refusal convertible back to that original ReactError. No new terminal_kind, panic, unreachable, Other/Failed fallback or string matching. `AgentEvent::from_error` becomes an explicit fallible boundary with the same distinction. `AgentTurnDriver::drive` also returns `Result<TurnReceipt>` because its existing setup, stream and sink error paths can receive the observation and no existing TurnOutcome can represent it. Its callers propagate the error; normal receipt fields remain identical. This is an intentional Rust source API migration required by B; callers replace infallible conversion with checked conversion/propagation, not default failure construction.

Migrate all actual conversion consumers and tests, including aliases/into-style uses found by full repository search. An observation in a raw stream remains the original Err through the normalizer; it is not emitted as AgentEvent::Error and does not trigger a synthetic missing-terminal Failed at EOF. Turn/Team/Subagent terminal producers propagate this knowledge or preserve the original pending owner before classification. The physical owner must not return a temporary observer error as a joined dispatch result or resolve/CAS error. SDK Host and other external Rust consumers require their own explicit source adaptation; this does not accept the new variant as a cross-language API. CLI consumer compile is checked as a consumer, not used as a qualification rule for framework API.


### Live source can resolve its own observation

A source-origin ExecutionNotSettled is physical knowledge, not the first business failure. Continue the same original source and the existing envelope normalizer after that observation, without re-execution or replay of previously delivered events. A later explicit terminal from that same bound source, after the latest matching observation, followed by its actual EOF can resolve that source's uncertainty. Preserve the original first business cause, terminal value fields, sequence and event identities. A later cleanup confirmation cannot replace an already-known result. EOF by itself, a normalizer-generated missing-terminal/ordinary-error envelope, cancellation notification, successful delivery or a sink error is not such proof. A new source observation after the last real terminal invalidates an earlier closing candidate.

The immutable source instance and EventIdentity retain their original run/execution/attempt binding. Match the observation run against the existing request run identity (or its existing turn fallback), and match the execution Option exactly; do not fill an absent identity to make it match. An observation for a foreign owner/attempt is not discharged by this source's terminal. Track source knowledge separately from sink/delivery observations, even when their string identities happen to coincide. A real source close cannot clear uncertainty reported by a different delivery authority. No new generation field, proof API, status, registry, payload queue or owner is introduced.

Core cancellation and invocation wrappers must preserve necessary original closing information while retaining the same producer. First cancellation records the original cause and continues physical drain; when it would otherwise manufacture the only cancellation terminal, defer that terminal until the original EOF. It may publish that one cancellation cause only if no unresolved source observation remains: either none occurred, or an original explicit source terminal followed the latest source observation. A source observation later than that terminal prevents cancellation synthesis at EOF. Earlier real business terminal/error remains first and is not replaced by a later cancel. Drains after an ordinary error retain original source terminal confirmations and source observations needed by the original consumer; they do not replay post-terminal chunks or publish another canonical business terminal. The existing envelope normalizer still owns canonical terminal delivery. The five-second observer remains in RuntimeTaskService, not a new wrapper deadline.

Only the original owner may use a valid closing candidate together with actual source closure to finish its existing input lifecycle, return the original receipt and perform the same exact-claim CAS, then retire the original control/admission resources once. Existing input settlement already clears the private observation through the same watch. Do not clear a slot or Core fence merely because an observer stopped waiting, a claim disappeared, a delivery failed or a local future returned. Setup observations with no source, a source ending without a valid later terminal, wrong owner/generation and unresolved delivery observations remain unknown. This does not promise automatic recovery when no authoritative late source exists.

Ordinary non-draining/bounded ToolManager methods retain their existing policy. No second supervisor, scheduler, result category or protocol is added.

### Scheduler occurrence physical ownership

The existing Scheduler occurrence journal and DeliveryLedger remain the sole occurrence/claim authority. Four genuine before failures show callback observation being persisted as Failed/last_result, started callback ownership being dropped/reclaimed, and handle-only shutdown losing the sole resource root while the original file backend remains held. New scheduled and manual occurrences use a private, versioned physical-settlement payload contract committed in the original Persisted record; original EffectStarted is durably confirmed before the callback factory is invoked. A versioned protected wrapper deliberately omits the legacy top-level payload shape, so an old scheduler reader rejects protected records rather than silently ignoring a new field. The new reader accepts actual old flat payload bytes as legacy at-least-once history. Historical owner loss can produce its original first replay; every newly admitted physical attempt, including that replay, must acquire protection before its callback effect. A new genuine counter demonstrates why legacy is not a permanent exemption: a current callback returned typed unknown while its old payload remained legacy, and reopening admitted a different attempt while the same backend was held.

The original ledger has no legal payload update: duplicate Persisted is refused, Deferred permits retry and TurnSettled fabricates physical closure. Extend only canonical DeliveryEvent::EffectStarted with `replacement_payload: Option<Payload>`, default absent and omitted for None. After exact current claim and Claimed-phase validation, that same event atomically installs the supplied payload and records the original effect start. Message/route/attempt/sequence/turn ownership are not replaced. Scheduler supplies its protected V1 payload before each newly admitted callback, and the existing recovery Claimed+EffectStarted prepared batch supplies the same protection for the new recovered attempt. No snapshot-only rewrite or second event/store is used. The returned claim carries the upgraded payload as well. Wrong attempt/phase must leave journal sequence and projection unchanged; new protection is durably confirmed before invoking the callback factory.

Existing non-Scheduler prepare_transition/begin_effect emits None, preserving genuine old event bytes and ordinary behavior. Public Rust EffectStarted literal/match consumers migrate the new optional field; no other DeliveryEvent variants, DeliveryRecord fields, TaskStatus or SDK wire membership change. The old DeliveryEvent decoder denies unknown fields, so Some rejects downgrade readers; protected private payload wrappers also reject old checkpoint decoders. Recovery of old history remains allowed, but loss of a newly protected recovered callback no longer authorizes another replay.

Every newly admitted callback has one retained original execution owner, following the existing owned-mutation spawn/join pattern. A private owner carrier clones only the original FireFn, same occurrence authority, mutation owner, store, tasks and control capabilities; it is not another Runner/loop or registry. It owns the original CallbackOwnerGuard and callback future through callback completion and the original result projection. The guard is only a liveness hint, not the physical resource authority: after a callback returns typed unknown its guard may leave the live set, while the durable protected claim remains and its existing parent retains FireFn/store/control resources. Public drain/run_once waiting borrows its JoinHandle; waiter drop detaches that same owner rather than dropping the callback. Scheduler cancellation signals the existing token; it cannot drop an admitted callback or requeue it to manufacture shutdown. Callback factory/poll panic or loss of its original owner leaves the protected durable EffectStarted claim, without a physical receipt or automatic replacement. No permanent fake task, self-cycle or replacement execution is used.

A callback's typed ExecutionNotSettled returns losslessly to its current observer before any last_run update or DeliverySettlement. Its protected original EffectStarted/occurrence/attempt remains nonterminal across reopen. There is no existing public occurrence-result/recovery API promising the callback's concrete run/execution fields after restart; the durable protected occurrence/attempt is the recovery fence, not a fabricated late receipt. A callback that has already returned unknown has no new canonical late-join interface; source-less uncertainty cannot be cleared by a timer, missing active hint, disconnect or reopening. The active-attempt set remains only a process liveness hint. Recovery skips protected started effects while retaining the original replay policy for truly legacy unprotected journal records. Independent later occurrences are not blocked by a second global FIFO or quota.

A real callback success or ordinary known error after original future completion retains the original last_run projection and terminal delivery policy, exactly once for that original claim. The owner performs those original writes even if its borrowed waiter has gone. A callback-owner join failure cannot be converted into Other/Failed settlement; observation identity is the existing canonical SchedulerInvocation occurrence_id/attempt_id, with no newly minted run. SchedulerHandle joins loop completion separately from protected still-unsettled callback knowledge and returns nonterminal observation while such claims remain, never claiming physical shutdown from an empty process-local set. Waiting for cooperative cleanup may remain pending when no callback result exists.

The existing SchedulerHandle is the explicit parent root for handle-only callers. It retains the original Arc<SchedulerRunner>, hence the original FireFn and store/control/authority capabilities. Its Rust `join` and `shutdown` receivers become `&mut self`: a pending borrowed wait polls the original `Option<JoinHandle<()>>` by mutable reference without taking it. Only actual loop join completion removes that handle and caches any join error, preventing repeat-poll panic. Returning unknown leaves the same parent handle in the caller, and a repeated join observes only the same loop result and original journal; it never creates another callback. Ordinary call sites that bind immutable handles migrate to mutable binding; API signature references are updated. This is a necessary Rust source receiver migration, not a new method/wire contract.

The strong graph is caller -> SchedulerHandle -> original Runner -> FireFn/store/control/occurrence authority; the loop and admitted task retain only the same original capabilities. CallbackOwnerGuard -> Weak<OccurrenceAuthority> has no strong reverse edge, and neither authority nor Runner owns the handle/task. No self-cycle or permanent task substitutes for a parent. run_once already borrows its caller-owned Runner. Callers that need to preserve unknown ownership keep that Runner or the returned SchedulerHandle; explicitly destroying the last parent or using a temporary handle is distinct from a shutdown method silently consuming its only parent. All-parent destruction does not promise authority immortalization or automatic recovery. The handle-only strong test uses a sole original FireFn guard/permit and actual held file backend, then joins that same backend before explicitly leaving the parent scope; final Weak/guard/permit release proves no internal cycle.

Legacy at-least-once replay controls use genuine old flat records and preserve their original initial replay. A current recovery callback is a new physical attempt and is protected before its effect; it is never relabeled legacy to make repeated abort/replay expectations pass. Control histories needing multiple old admitted attempts must encode those actual legacy records before opening the new execution owner, rather than using a new protected admission as fake history. Strong current tests retain the actual file producer/guard until release and the same join, keep the same claim while held, prove no reclaimed attempt after borrowed drop/shutdown, and verify normal success/error projection plus restart fencing. Rust source migrations are the borrowed SchedulerHandle receivers and the optional EffectStarted payload field at all actual literal/match sites; existing ordinary event bytes stay unchanged when it is absent. The private protected payload format applies before every current physical admission, including a new attempt recovered from old history. Downgrade of a journal containing protected records fails closed. Explicit user deletion is not physical proof or an implicit recovery API.

## Recovery and limits

A foreign Agent setup may return ExecutionNotSettled without a stream/JoinHandle. Its identity is not a closure receipt and cannot be repaired by re-running drive. ACP keeps the original active Session lease in the same RunEntry's explicit uncertain-owner slot, remains Running/no receipt, and rejects admission/close completion until authoritative closure/fence. No leaked lease via mem::forget or permanently parked fake owner task. Existing receipts release that same slot; disconnect/revocation alone do not. CLI/SDK consumers separately preserve their existing resources/unknown fence under the same rule.

ACP isolates that Run observation from the official connection actor's fatal
task result. The original Running lifecycle payload holds the structured driver
error under the same mutex as settlement, retaining its original lease.
`RunEntry::wait_result()` returns a real receipt first or that observer error;
it pre-registers notification and supports existing and later waiters.
`wait_receipt()` remains receipt-only. A committed receipt rejects subsequent
observation writes. Standard Prompt uses the observer result for both normal
and request-cancel waits and sends a request error without receipt persistence.
The shared prepared task finishes successfully only after recording its Run
error; actual transport/spawn failures remain errors. The official pinned ACP
runtime makes task errors connection-fatal, while its existing request error
responder isolates a single request. No SDK catch, second Run authority, new
terminal, retry or language contract is introduced. See ADR0088's ACP refinement.

Non-cooperative work retains its original claim and execution limits indefinitely; new work is subject to existing admission, not an unbounded replacement supervisor pool. A caller can stop waiting after grace without releasing those limits. Transport disconnect alone does not prove remote finally. Restart without a matching original generation/physical receipt remains AuthorityUnknown; reconciliation cannot redispatch an existing Running claim. Existing exact CAS can settle only after authoritative closure/fence. A local process's actual owned death is evidence; a missing local registry is not.

## References and decision

[Tokio graceful shutdown](https://tokio.rs/tokio/topics/shutdown) separates signaling cancellation from waiting for completion. [Tokio JoinHandle](https://docs.rs/tokio/latest/tokio/task/struct.JoinHandle.html) documents detach on handle drop. [Python cancellation](https://docs.python.org/3/library/asyncio-task.html) separates cancellation request from finally cleanup. These existing design references support retained ownership, not repository proof. The Root coordinator refreshed the official Tokio shutdown and JoinHandle references successfully in this session; cancellation request and detached observation still do not establish physical completion.

The official [Temporal cancellation types](https://typescript.temporal.io/api/namespaces/common#activitycancellationtype) distinguish immediate cancellation observation from waiting for activity cancellation completion. This design reuses that separation and Tokio's retained task semantics, not Temporal's server or automatic lease retry policy. The current official pages were fetched successfully for this Scheduler increment; neither external reference proves repository behavior.

Option A (forced abort plus a new stable physical receipt contract) was considered in the historical proposal and not selected. User selected B: retain the original owner, expose bounded observation. This supersedes prior forced-abort grace wording in ADR0058/0060 only where it equated local abort/join with physical producer closure. Rollback to old abort behavior reintroduces the known defect; it is not behavior equivalence.
