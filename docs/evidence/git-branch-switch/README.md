# GitBranchTool: branch selection must not restore a same-named path

The original published a634 tool used `git checkout -- <target>` for `git_branch.switch`. Git interprets arguments after that separator as paths. In test-owned repositories, an existing branch without a same-named file therefore failed with pathspec error. With a same-named tracked file carrying dirty Unicode edits, the command returned success, left HEAD on main and restored the file from the index. Complete original HEAD, branch refs, logical index entries, status and top-level tracked/sentinel file SHA observations are preserved in original-cli-counterexamples.json. No user repository was used.

The same real GitBranchTool regression suite, against the original production command, passed one invalid-target test and failed three meaningful cases (normal switch, same-named dirty file, conflicting dirty branch). Before-production-fix.rs preserves that exact source including its new test module; before-actual-run.json/log record exit 101. The earlier cancelled dependency build (130) never ran the suite and is not counted as a product failure. No unsafe fixture API remained in the actual compiled before run.

The production change uses native `git switch -- <target>`, matching the existing managed-worktree implementation. The existing bounded Git process helper and working-directory context remain unchanged. Empty/option-like targets fail explicitly before Git runs. Invalid/missing branch names and dirty conflicts are rejected by Git without force; compatible dirty edits remain. No branch/path ambiguity, path restore, SDK Git cache, second repository authority, new API/schema/dependency or permission rule is added. Create/delete/list behavior is unchanged.

Four actual ToolContext-based tests pass after the fix. They cover an existing branch with no same-named file, dirty tracked file sharing the branch name, dirty conflict with a different target commit, and invalid/leading-option/missing targets. Every scenario checks original HEAD/branch/heads refs/logical index/worktree status/file SHA facts; successful same-commit switches change only symbolic HEAD, while failures retain the complete protection snapshot. The before/after test bodies are identical when formatted by rustfmt. Original dirty data is never force-discarded.

Same-source echo_tools lib/all-features passes 227 tests with two existing opt-in ignored tests. Strict all-target/all-feature Clippy `-D warnings`, cargo fmt --all and fmt check pass. Source and actual receipts are frozen in receipt.json and source/. Full framework six merge gates, current-main reconciliation, independent review, remote CI and publication remain separate. The feature matrix is not triggered: no manifest, optional dependency, production cfg or cross-crate public API changed.
